# 反理性化清单 — 常见捷径诱惑 vs 正确做法

> 当你发现自己在想以下这些话时，停下来，你正在走捷径。

| 你的内心独白 | 现实 | 正确做法 |
|-------------|------|---------|
| "这个改动很小，不需要 Phase 0" | 小改动照样能破坏管道 | 跑 Phase 0，哪怕只输出 3 行 |
| "我先改了再跑测试" | 不跑测试 = 盲改 | 改完立即 `tsc + test`，不要攒到最后 |
| "这个 i18n key 不重要，先只改英文" | 缺失 key 会导致中文站崩溃 | 永远 en/zh 同时改 |
| "这个文件虽然在冻结区域，但我只是微调" | 冻结区域没有「微调」概念 | 停下，问用户 |
| "加个 console.log 调试一下，一会儿删" | 你不会删。它会进入生产环境 | 用 `if (__DEV__)` 包裹 |
| "这个功能简单，不需要拆任务" | 超过 3 文件的变更回滚成本翻倍 | 拆分，每个任务 1-3 文件 |
