# /ux-audit — 用户体验审计

> Nielsen 启发式 + 认知走查 + 微文案审计 + 无障碍检查，专为 Deep Dive 双语职业探索旅程定制。
> 所有输出使用中文。

## 触发条件

用户说 "UX 审计"、"ux audit"、"体验检查"、"流程困惑"、"文案清晰度"、"无障碍"、"accessibility" 时激活。

## 可用工具

Bash, Read, Write, Edit, Glob, Grep, Agent

## 模式总览

| 模式           | 命令                    | 做什么                                       | 预估耗时 |
| -------------- | ----------------------- | -------------------------------------------- | -------- |
| **启发式评估** | `/ux-audit` (默认)      | Nielsen 10 条 × Deep Dive 场景               | ~10min   |
| **认知走查**   | `/ux-audit walkthrough` | 模拟新手完整旅程：着陆→Quick Dive→报告→教练  | ~15min   |
| **文案审计**   | `/ux-audit copy`        | 微文案系统审计：按钮、标签、空状态、错误信息 | ~10min   |
| **无障碍**     | `/ux-audit a11y`        | WCAG 2.1 AA 核心检查                         | ~5min    |
| **双语对比**   | `/ux-audit i18n`        | en↔zh 文案质量对比、文化适应性               | ~10min   |
| **全量**       | `/ux-audit full`        | 以上全部                                     | ~30min   |

## 模式 1 — Nielsen 启发式评估 (`/ux-audit` 默认)

> 将 Nielsen 10 条启发式原则适配到 Deep Dive 的具体场景。

### H1: 系统状态可见性 (Visibility of System Status)

| Deep Dive 场景         | 检查项                                      | 文件                                    |
| ---------------------- | ------------------------------------------- | --------------------------------------- |
| Quick Dive 30 题进度   | 进度条/题号显示？当前位置清晰？             | `components/questionnaire/`             |
| Deep Dive 86 题进度    | 章节进度 + 总进度双层显示？                 | 同上                                    |
| Immersive 38 题 (7 章) | 章节名称 + 伙伴状态 + 深度指示？            | `components/immersive-explore/`         |
| 报告生成中             | 等待 UI（180s！）有进度指示？不是空白等待？ | `app/[locale]/(app)/report/`            |
| 教练回复中             | SSE 流式有"正在输入"指示？                  | `components/features/coaching-chat.tsx` |
| 邀请码验证             | 成功/失败即时反馈？                         | `components/features/`                  |

### H2: 系统与真实世界匹配 (Match Between System and Real World)

| Deep Dive 场景 | 检查项                                                       |
| -------------- | ------------------------------------------------------------ |
| 深海隐喻一致性 | 从 "surface" 到 "abyss" 的视觉深度是否全程一致？             |
| 职业术语       | 是否用用户能理解的语言而非行业术语？(如 "RIASEC" 不直接暴露) |
| 原型命名       | 12 型名称是否直觉易懂？(如 "系统建筑师" vs "RE 型")          |
| 文化适应       | 英文版和中文版的隐喻是否都成立？                             |

### H3: 用户控制与自由 (User Control and Freedom)

| Deep Dive 场景 | 检查项                                   |
| -------------- | ---------------------------------------- |
| 问卷中途退出   | 能否保存进度并稍后继续？明确的退出路径？ |
| 答案修改       | 能否返回修改之前的答案？                 |
| 报告重新生成   | 不满意时能否重新生成？                   |
| 教练对话       | 能否结束对话？清除记忆？                 |

### H4: 一致性与标准 (Consistency and Standards)

| Deep Dive 场景 | 检查项                                    |
| -------------- | ----------------------------------------- |
| 按钮样式       | 主操作/次操作/危险操作有统一样式？        |
| 导航模式       | 返回/关闭/取消行为一致？                  |
| 颜色含义       | 品牌色/原型色/状态色不混淆？              |
| 术语一致       | "Quick Dive"/"Deep Dive" 等术语全站统一？ |

### H5: 错误预防 (Error Prevention)

| Deep Dive 场景 | 检查项                          |
| -------------- | ------------------------------- |
| 必答题未答     | 提交前验证 + 定位到未答题目？   |
| 重复提交       | 按钮防抖/禁用？报告不重复生成？ |
| Session 过期   | 30 天 session 过期前有提醒？    |
| 邀请码格式     | 输入时实时验证格式？            |

### H6: 识别而非回忆 (Recognition Rather Than Recall)

| Deep Dive 场景 | 检查项                    |
| -------------- | ------------------------- |
| 返回时上下文   | 回到问卷时知道在哪里？    |
| 报告导航       | 5 章报告有目录/锚点导航？ |
| 教练历史       | 之前的对话上下文可见？    |

### H7: 灵活性与使用效率 (Flexibility and Efficiency)

| Deep Dive 场景 | 检查项                          |
| -------------- | ------------------------------- |
| 快捷操作       | 键盘导航支持？(问卷 1-5 快捷键) |
| 分享           | 报告可一键分享？                |

### H8: 美学与极简设计 (Aesthetic and Minimalist Design)

| Deep Dive 场景 | 检查项                                |
| -------------- | ------------------------------------- |
| 信息密度       | 每屏信息量是否过载？                  |
| 视觉噪音       | 装饰性元素是否干扰内容？              |
| 深海美学       | 玻璃态/发光效果是增强还是分散注意力？ |

### H9: 帮助用户识别、诊断和恢复错误 (Help Users Recognize Errors)

| Deep Dive 场景 | 检查项                                  |
| -------------- | --------------------------------------- |
| API 错误       | 网络失败/LLM 超时有友好的中文错误信息？ |
| 表单错误       | 注册/登录错误信息具体明确？             |
| 报告生成失败   | 有重试按钮 + 清晰的失败原因？           |

### H10: 帮助与文档 (Help and Documentation)

| Deep Dive 场景 | 检查项                        |
| -------------- | ----------------------------- |
| 首次使用引导   | Quick Dive 开始前有简短说明？ |
| FAQ            | 常见问题有解答？              |
| 隐私说明       | 数据用途说明清晰可见？        |

### 输出格式

```
🔍 Nielsen 启发式评估报告

| # | 启发式原则 | 评分 (1-5) | 关键发现 |
|---|-----------|-----------|----------|
| H1 | 系统状态可见性 | 4/5 | 报告生成等待 UI 缺少进度指示 |
| H2 | 真实世界匹配 | 5/5 | 深海隐喻一致 |
| ... | ... | ... | ... |

综合评分: X/50
```

## 模式 2 — 认知走查 (`/ux-audit walkthrough`)

> 模拟一个从未用过 Deep Dive 的新手，走完完整旅程。

### 走查路径

```
1. 着陆页 → 理解产品是做什么的？
2. 注册/登录 → 流程清晰？多久能开始？
3. 选择 Quick Dive → 知道这是什么？要多久？
4. 30 题问卷 → 题目清晰？知道怎么选？进度可见？
5. 完成 → 知道接下来做什么？
6. 查看 Profile → 理解结果含义？
7. 生成报告 → 等待过程（~180s）可接受？
8. 阅读报告 5 章 → 内容有价值？想继续？
9. 开始教练对话 → 知道怎么用？
10. 分享/返回 → 能找到入口？
```

### 每步检查

| 维度         | 问题                                          |
| ------------ | --------------------------------------------- |
| **可发现性** | 下一步操作明显吗？CTA 足够突出？              |
| **可理解性** | 用户知道这一步在做什么吗？                    |
| **反馈**     | 操作后有即时反馈吗？                          |
| **错误恢复** | 如果走错了能回来吗？                          |
| **情绪体验** | 这一步用户会感到什么？（兴奋/焦虑/无聊/困惑） |

### 输出格式

```
🚶 认知走查报告

步骤 1 — 着陆页
  可发现性: ✅ CTA 突出
  可理解性: ✅ 产品定位清晰
  反馈: N/A
  错误恢复: N/A
  情绪: 好奇 → 兴趣
  问题: 无

步骤 7 — 报告生成
  可发现性: ✅ 生成按钮明显
  可理解性: 🟡 用户可能不知道要等 180s
  反馈: ❌ 缺少进度指示
  错误恢复: ❌ 失败后无重试
  情绪: 期待 → 可能焦虑（长时间等待）
  问题: [P1] 180s 等待需要进度 UI

阻塞点汇总: X 个
摩擦点汇总: X 个
```

## 模式 3 — 文案审计 (`/ux-audit copy`)

### 审计范围

```bash
# 扫描所有 i18n 字典
find lib/i18n/dictionaries/en -name "*.json" | sort
find lib/i18n/dictionaries/zh -name "*.json" | sort
```

### 逐类审计

| 文案类型       | 检查标准                      | 示例                                 |
| -------------- | ----------------------------- | ------------------------------------ |
| **CTA 按钮**   | 动词开头、明确动作、≤4 字     | "开始探索" ✅ "提交" ❌              |
| **标题**       | 简洁、有吸引力、传递价值      | "你的职业 DNA" ✅ "评估结果" ❌      |
| **说明文字**   | ≤2 句、解答"为什么"和"接下来" |                                      |
| **错误信息**   | 说明出了什么问题 + 怎么解决   | "网络超时，请重试" ✅ "Error 500" ❌ |
| **空状态**     | 说明为什么空 + 引导下一步     |                                      |
| **确认对话框** | 明确后果、CTA 非 "确定/取消"  | "删除报告" / "保留" ✅               |
| **加载状态**   | 有趣/有用，非"Loading..."     | "正在为你绘制职业地图..." ✅         |
| **成功信息**   | 确认完成 + 引导下一步         |                                      |

### Deep Dive 专项

| 检查项                      | 验证方法                   |
| --------------------------- | -------------------------- |
| 12 型原型名称是否直觉易懂   | 中英文名称都不需要额外解释 |
| 报告 5 章标题是否引发阅读欲 | 非技术性命名               |
| 教练对话开场白是否温暖      | 非机械化                   |
| 隐私说明是否让人安心        | 数据用途透明、不引发焦虑   |
| 题目措辞是否中性无引导      | 心理测量专业标准           |

## 模式 4 — 无障碍检查 (`/ux-audit a11y`)

### WCAG 2.1 AA 核心检查

| 原则       | 检查项             | 验证方法                                     |
| ---------- | ------------------ | -------------------------------------------- | --------------- |
| **可感知** | 图片有 alt 文本    | `grep -rn "<img\|<Image" --include="\*.tsx"  | grep -v "alt="` |
| **可感知** | 颜色对比度 ≥ 4.5:1 | 检查 `globals.css` 中前景/背景组合           |
| **可感知** | 不仅用颜色传递信息 | 状态同时有图标/文字                          |
| **可操作** | 键盘可导航         | Tab 顺序合理、focus 可见                     |
| **可操作** | 触摸目标 ≥ 44px    | 按钮/链接最小尺寸                            |
| **可理解** | 语言标记           | `<html lang="en">` / `<html lang="zh">`      |
| **可理解** | 表单有 label       | `<input>` 有关联的 `<label>` 或 `aria-label` |
| **健壮**   | 语义化 HTML        | 使用 `<main>`, `<nav>`, `<section>` 等       |
| **健壮**   | ARIA 正确          | `role`, `aria-*` 属性使用正确                |

```bash
# 快速检查缺失的 alt
grep -rn "<img\|<Image" components/ app/ --include="*.tsx" | grep -v "alt=" | head -20

# 查找缺少 label 的 input
grep -rn "<input\|<Input\|<textarea\|<select" components/ app/ --include="*.tsx" | grep -v "aria-label\|htmlFor\|<label" | head -20

# 查找 focus 管理
grep -rn "focus\|tabIndex\|autoFocus" components/ --include="*.tsx" | head -20
```

## 模式 5 — 双语对比 (`/ux-audit i18n`)

### 检查清单

| 检查项           | 验证方法                                                   |
| ---------------- | ---------------------------------------------------------- |
| en/zh 键完全同步 | `npm run lint:i18n`                                        |
| 中文长度不溢出   | 中文通常比英文短，但偶尔更长                               |
| 英文不含中文字符 | `grep -rP '[\x{4e00}-\x{9fff}]' lib/i18n/dictionaries/en/` |
| 中文不含英文大段 | 品牌名/专有名词例外                                        |
| 日期/数字格式    | en: "March 23" / zh: "3月23日"                             |
| 语气一致性       | 英文正式但温暖 / 中文亲切但专业                            |
| 隐喻翻译质量     | 深海隐喻在两种语言中都自然？                               |

## 关键规则

1. **用户视角** — 以从未见过产品的新手角度评估，不受代码知识影响
2. **只读审计** — 不修改文件，只报告发现
3. **截图证据** — 使用 `/preview` 获取实时截图，每个问题附截图证据
4. **量化优先** — "H1 得分 3/5" 好过 "系统状态可见性一般"
5. **优先级标注** — P0 (用户无法完成任务) / P1 (严重困惑) / P2 (体验摩擦) / P3 (锦上添花)
6. **中文输出** — 所有报告使用中文
7. **参考设计规范** — 评估时对照 `.claude/skills/deepdive-design/SKILL.md`
