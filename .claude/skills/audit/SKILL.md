# /audit — 全维度业务测试统一入口

> 一个命令，5 维度审计全部跑完，输出一张综合健康仪表盘。
> 整合 `/biz-audit` + `/perf-audit` + `/ux-audit` + `/security-audit` + `/edge-audit`。
> 所有输出使用中文。

## 触发条件

用户说 "全面审计"、"audit"、"全套测试"、"业务测试"、"产品体检"、"上线前检查" 时激活。

## 可用工具

Bash, Read, Write, Edit, Glob, Grep, Agent

## 模式总览

| 模式       | 命令            | 做什么                           | 预估耗时 |
| ---------- | --------------- | -------------------------------- | -------- |
| **快速**   | `/audit quick`  | 每维度最快冒烟检查，5 分钟出结果 | ~5min    |
| **标准**   | `/audit` (默认) | 每维度默认模式，覆盖关键检查项   | ~30min   |
| **全量**   | `/audit full`   | 每维度最深度审计，零遗漏         | ~60min   |
| **单维度** | `/audit {维度}` | 跳转到对应 Skill（见下方路由表） | 按 Skill |

### 单维度路由

| 参数       | 跳转到            | 等价于         |
| ---------- | ----------------- | -------------- |
| `biz`      | `/biz-audit`      | 业务逻辑正确性 |
| `perf`     | `/perf-audit`     | 性能瓶颈       |
| `ux`       | `/ux-audit`       | 用户体验       |
| `security` | `/security-audit` | 安全漏洞       |
| `edge`     | `/edge-audit`     | 边缘场景       |

## 执行流程

### 阶段 0 — 公共前置检查

> 所有模式共用，失败则标注但不阻塞后续审计。

```bash
# 1. TypeScript 编译
npx tsc --noEmit 2>&1 | tail -20

# 2. 单元测试
npm run test 2>&1 | tail -20

# 3. ESLint + i18n
npm run lint 2>&1 | tail -10
npm run lint:i18n 2>&1 | tail -10

# 4. Dev server (UX/Edge 审计需要)
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
```

**报告格式：**

```
⚡ 前置检查
  tsc:    ✅ 0 错误 | ❌ N 错误
  vitest: ✅ X/Y 通过 | ❌ N 失败
  lint:   ✅ 0 错误 | ❌ N 错误
  i18n:   ✅ 同步 | ❌ 不同步
  dev:    ✅ 运行中 | ⚠️ 未启动（UX/Edge 部分跳过）
```

### 阶段 1 — 五维度并行审计

> 使用 Agent 工具并行启动 5 个审计子任务，最大化效率。

根据模式选择每个维度的深度：

| 维度         | `/audit quick`                           | `/audit` (标准)             | `/audit full`                      |
| ------------ | ---------------------------------------- | --------------------------- | ---------------------------------- |
| **业务逻辑** | `/biz-audit quick` (冒烟)                | `/biz-audit` (管道审计)     | `/biz-audit full` (全量)           |
| **性能**     | `/perf-audit quick` (包体积+明显泄漏)    | `/perf-audit` (6 维度)      | `/perf-audit full` (含 build 分析) |
| **用户体验** | `/ux-audit a11y` (无障碍快检)            | `/ux-audit` (Nielsen 10 条) | `/ux-audit full` (含认知走查+文案) |
| **安全**     | `/security-audit quick` (守卫+CSRF+注入) | `/security-audit` (7 维度)  | `/security-audit full` (含 STRIDE) |
| **边缘场景** | `/edge-audit quick` (超时+错误边界)      | `/edge-audit` (6 维度)      | `/edge-audit full` (含兼容性)      |

**并行执行策略：**

```
启动 5 个 Agent 并行执行各维度审计：

Agent 1: "按 /biz-audit {mode} 的检查清单审计，只读不改，输出结构化结果"
Agent 2: "按 /perf-audit {mode} 的检查清单审计，只读不改，输出结构化结果"
Agent 3: "按 /ux-audit {mode} 的检查清单审计，只读不改，输出结构化结果"
Agent 4: "按 /security-audit {mode} 的检查清单审计，只读不改，输出结构化结果"
Agent 5: "按 /edge-audit {mode} 的检查清单审计，只读不改，输出结构化结果"
```

### 阶段 3 — 交叉分析

> 在各维度独立审计之后，分析跨维度关联问题。

**交叉关注点：**

| 交叉维度    | 检查什么                                                             |
| ----------- | -------------------------------------------------------------------- |
| 安全 × 边缘 | SSE 断连重连是否暴露 session token？弱网下 CSRF token 过期如何处理？ |
| 性能 × UX   | LLM 180s 超时对应的等待 UI 是否到位？包体积对首屏体验的影响？        |
| 业务 × 安全 | 评分数据篡改能否绕过原型分配？报告 URL 能否被他人访问？              |
| 业务 × 边缘 | 全部平分时原型分配逻辑？只答一半提交会怎样？                         |
| UX × 边缘   | 弱网下加载状态文案是否友好？i18n 切换中途的用户感知？                |

**输出：**

```
🔗 交叉分析

| # | 关联维度 | 场景 | 风险 | 级别 |
|---|----------|------|------|------|
| 1 | 安全×边缘 | SSE 重连时 session 可能泄露 | 中 | P1 |
| 2 | 性能×UX | 180s 等待无进度=用户流失 | 高 | P1 |
```

## 综合评分计算

| 维度     | 权重 | 理由                          |
| -------- | ---- | ----------------------------- |
| 业务逻辑 | 25%  | 评分管道正确性 = 产品核心价值 |
| 安全     | 25%  | 用户数据安全 = 不可谈判       |
| 性能     | 20%  | 180s 报告 + SSE = 高感知延迟  |
| 用户体验 | 15%  | 双语旅程质量                  |
| 边缘场景 | 15%  | 真实环境鲁棒性                |

**综合评分 = Σ(维度评分 × 权重)**

**质量门控：**

| 评分   | 等级            | 含义                       |
| ------ | --------------- | -------------------------- |
| 90-100 | 🟢 **PASS**     | 可安全发布                 |
| 70-89  | 🟡 **CONCERNS** | 有注意事项，建议修复后发布 |
| 50-69  | 🟠 **REWORK**   | 需要修复关键问题           |
| 0-49   | 🔴 **FAIL**     | 阻塞发布                   |

**硬规则**: 任何 P0 = 自动降级为 🟠 REWORK，无论综合评分多高。

## 关键规则

1. **只读审计** — 全程不修改任何文件，只报告发现
2. **并行最大化** — 5 维度用 Agent 并行执行，不串行等待
3. **统一评分** — 所有维度用相同的 1-10 评分标准 + P0/P1/P2 分级
4. **交叉分析** — 不止看单维度，还分析跨维度组合风险
5. **基线对比** — full 模式自动存基线，支持回归追踪
6. **中文输出** — 综合报告和各维度子报告全部用中文
7. **P0 = 阻塞** — 任何 P0 发现自动降级整体评分
