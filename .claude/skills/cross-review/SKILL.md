# /cross-review — 跨模型代码审查

> 使用第二个 AI 模型对当前分支的变更进行独立审查，获得不同视角的代码反馈。
> 所有输出使用中文。

## 触发条件

用户说 "cross review"、"跨模型审查"、"第二意见"、"换个模型看看"、"codex" 时激活。

## 可用工具

Bash, Read, Grep, Glob, Agent, WebFetch

## 模式

| 模式     | 命令                                      | 说明                                         |
| -------- | ----------------------------------------- | -------------------------------------------- |
| **审查** | `/cross-review` 或 `/cross-review review` | 对当前分支 diff 进行代码审查，输出 PASS/FAIL |
| **挑战** | `/cross-review challenge`                 | 对抗性分析：边界情况、竞态条件、安全漏洞     |
| **咨询** | `/cross-review consult {问题}`            | 就特定技术问题获取第二意见                   |

## 工作流程

### 阶段 1 — 收集变更

```bash
# 获取当前分支相对于 main 的所有变更
git diff main...HEAD

# 获取变更文件列表
git diff --name-only main...HEAD

# 获取提交历史
git log main...HEAD --oneline
```

如果没有分支差异，退而使用未提交的变更：

```bash
git diff HEAD
git diff --cached
```

### 阶段 2 — 构建审查上下文

读取变更文件的完整内容（不只是 diff），理解：

- 变更的意图（从 commit message 推断）
- 受影响的模块和依赖
- 相关的类型定义和接口
- 现有的测试覆盖

### 阶段 3 — 生成审查 Prompt

根据模式构建不同的审查视角：

**审查模式 prompt 结构：**

```
你是一位资深代码审查者。请审查以下代码变更，关注：
1. 逻辑正确性 — 是否有 bug 或边界情况遗漏
2. 安全性 — 注入、XSS、敏感数据泄露
3. 性能 — N+1 查询、不必要的重渲染、内存泄漏
4. 可维护性 — 命名、结构、复杂度
5. 类型安全 — TypeScript 类型是否严密

对每个发现标记严重级别：
- [P1] 必须修复 — 会导致 bug 或安全问题
- [P2] 建议修复 — 会影响维护性或性能
- [P3] 可选改进 — 代码风格或最佳实践

最终给出 PASS 或 FAIL 判定。任何 P1 发现 = FAIL。
```

**挑战模式 prompt 结构：**

```
你是一位对抗性安全审查者。尝试从以下角度攻破这段代码：
1. 边界条件 — 空值、极端输入、并发
2. 竞态条件 — 异步操作顺序、数据库事务
3. 安全漏洞 — OWASP Top 10
4. 失败模式 — 外部服务超时、网络中断
5. 数据一致性 — 部分更新、幂等性

用最大力度寻找问题。宁可误报也不要漏报。
```

### 阶段 4 — 执行审查

使用 Agent 工具启动一个独立的审查 agent：

```
Agent(subagent_type: "security-reviewer", prompt: "审查以下变更...")
```

对于跨模型场景，也可以通过项目的 model-router 调用不同模型：

- Claude (当前模型) → 输出初始审查
- 然后用 Agent 以不同视角（如 security-reviewer）重新审查
- 对比两次审查的差异，标注 "仅模型A发现" / "仅模型B发现" / "双方一致"

### 阶段 5 — 输出报告

````markdown
# 跨模型代码审查报告

## 概要

- 分支: {branch_name}
- 变更文件: N 个
- 提交数: N
- 模式: {审查/挑战/咨询}
- 判定: ✅ PASS / ❌ FAIL

## 发现汇总

| #   | 严重级别 | 文件         | 行号 | 描述 | 来源     |
| --- | -------- | ------------ | ---- | ---- | -------- |
| 1   | [P1]     | path/file.ts | L42  | 描述 | 双方一致 |
| 2   | [P2]     | path/file.ts | L88  | 描述 | 仅审查A  |

## 详细分析

### [P1] 发现标题

**文件:** `path/file.ts:42`
**问题:** 详细描述
**建议修复:**

```code
修复代码
```
````

## 交叉对比

- 双方一致的发现: N 个 (可信度最高)
- 仅一方发现: N 个 (需人工判断)
- 相互矛盾: N 个 (列出两方观点)

```

## 关键规则

1. **只读操作** — 审查过程中不修改任何文件
2. **完整呈现** — 不要截断或简化审查结果，原样呈现
3. **标注来源** — 每个发现标明是哪个审查视角发现的
4. **中文输出** — 所有报告和分析使用中文
5. **尊重冻结区域** — 即使发现冻结区域的问题，也只报告不建议直接修改
6. **P1 = FAIL** — 任何 P1 级别发现自动判定 FAIL
```
